



🍦 아이스크림 가게 픽셀 게임 — 계획서

1\. 기술 구조

index.html (단일 파일) ├─ <canvas> 픽셀아트 렌더링 (image-rendering: pixelated, 저해상도 → 확대) ├─ CSS: UI 오버레이(키오스크 메뉴·HUD·모달), 픽셀 폰트(구글 "DungGeunMo" 대체 → 시스템 폰트 폴백) └─ JS: 상태머신 + 데이터(맛/케이크/미션) + 씬 렌더러 + 애니메이션 루프 - localStorage 로 용돈·도감·미션 진행 저장 - 외부 이미지 없이 픽셀 스프라이트를 코드(배열/도트 데이터)로 정의

2\. 화면 흐름 (씬)

\[타이틀] → \[가게 로비 / HUD: 용돈·날짜·미션] → \[키오스크] 콘/컵 선택 → 사이즈(싱글/더블/트리플) → 맛 선택(31종+이달의 맛) 또는 케이크 탭 → 케이크 6~8종 선택 → 가격 확인 → 결제(용돈 차감) → \[카운터] 직원이 통에서 스쿱으로 떠서 콘/컵에 쌓는 자동 애니메이션 (케이크는 냉장고에서 꺼내 상자에 담는 연출) → \[먹기] 받은 아이스크림을 클릭/터치 → 숟가락이 한 입 떠서 사라짐 시간 경과 시 녹아 흘러내림 → 다 먹으면 결과(만족도·용돈 보너스) → \[로비] 로 복귀, 다음 날 진행 가능

케이크 7종 (예): 미니 하트 케이크, 레인보우 케이크, 초코 파티 케이크, 스트로베리 돔, 민트초코 롤, 쿠키앤크림 박스, 캐릭터 케이크 — 각각 가격·용량(먹기 클릭 수)·구성 맛 보유

가격표: 싱글 3,200 / 더블 6,200 / 트리플 8,700 / 케이크 15,000~35,000 (게임 화폐, 조정 가능)

4\. 미션 — "용돈으로 사기"

매일 일일 용돈 지급(예: 8,000원, 날짜마다 변동)

그날 미션 예시: "5,000원 이하로 만족도 80 이상 달성", "3일 저축해서 케이크 사기", "이달의 맛 먹어보기"

만족도 계산: 다 먹기 완료 여부 + 녹기 전 먹은 비율 + 맛 조합 보너스

미션 클리어 → 용돈 보너스, 실패해도 진행은 가능

결과 화면에 미션 진행도·누적 통계 표시

5\. 핵심 연출

직원 애니메이션: 통으로 이동 → 스쿱 넣기 → 공 굴려 뜨기 → 콘 위로 이동 → 쌓기 (단수만큼 반복) → 건네주기, 약 1~1.5초/스쿱

먹기: 클릭 위치 기준 숟가락 스프라이트가 내려와 픽셀 덩어리 제거(스쿱마다 3~4입)

녹기: 타이머에 따라 스쿱 형태가 서서히 눌리며 아래로 흘러내리는 픽셀 드립 발생, 콘은 바닥으로 방울 떨어짐, 컵은 안에 고임. 다 녹으면 만족도 감소

6\. 구현 순서

뼈대: canvas 픽셀 렌더러 + 씬 전환 + HUD

맛/케이크/가격 데이터 + 키오스크 UI

직원 스쿱 애니메이션

먹기 + 녹기 시스템 + 결과 계산

용돈·미션·도감 + localStorage 저장

타이틀·효과음(Web Audio 비프음)·모바일 터치 대응 · 최종 점검

기본값으로 정한 사소한 것들 (필요하면 바꿔주세요)

콘/컵 사이즈: 싱글·더블·트리플 (컵은 파인트 대신 트리플까지 동일)

화면: 데스크톱 기준 + 모바일 터치 대응, 세로 화면도 축소 표시

사운드: 외부 파일 없이 간단한 8비트 효과음 (끄기 가능)





게임 파일을 만들어 공유했어요. claw.html 이 최신 완성본(단일 파일, 다운로드 후 브라우저에서 바로 열면 실행)이고, src.zip 은 분리된 소스(head.html / data.js / draw.js / game.js + 노드 테스트 스크립트)입니다.

① 실제로 끝낸 것

뼈대: 320×180 픽셀 캔버스(정수 배율 확대, image-rendering: pixelated), DungGeunMo 폰트(폴백 포함), 씬 상태머신(타이틀→로비→키오스크→카운터→먹기→결과), HUD·모달·토스트, 모바일 터치/세로 화면 축소

데이터: 맛 31종(색 3톤+토핑 점), 이달의 맛 8종 풀(게임 내 한 달=10일마다 시드 랜덤 1종), 케이크 7종(가격·입 수·형태·구성 맛), 가격표 싱글 3,200/더블 6,200/트리플 8,700

키오스크: 콘/컵 → 사이즈 → 맛 N개(중복 허용, NEW 표시, 이달의 맛 강조) / 케이크 탭 → 결제(용돈 차감·부족 시 비활성)

직원 연출: 카운터 뒤 상반신, 주문 맛 통으로 걸어가기 → 팔 뻗어 스쿠퍼 꽂기 → 스쿱 들기 → 콘 스탠드로 이동 → 포물선으로 쌓기(스쿱 수만큼 반복) → 건네기 / 케이크는 냉장고 문 열림→들고 옴→줄무늬 상자에 담고 뚜껑 닫기. 건너뛰기 버튼

먹기/녹기: 클릭·터치·스페이스로 스푼이 내려와 스쿱당 4입 제거(부스러기 파티클), 2.5초 후 녹기 시작해 스쿱이 눌리고 가라앉음, 드립 발생 → 콘은 테이블 웅덩이·컵은 안에 고이고 넘침, 다 녹으면 소실. 케이크는 베어먹은 단면 표시 + 서서히 눌림

결과·경제: 만족도(먹은 비율+완식+신선도+조합 보너스), 만족도 보너스 용돈, 미션 9종(가격 제한·이달의 맛·트리플·컵/콘·저축해서 케이크 등, 기한 있음) 판정·보너스 3,000원, 일일 용돈 7,000~8,500원, 도감(이달의 맛 별칸)·통계, localStorage 저장, 8비트 효과음(끄기 가능)

검증: node 스텁으로 전 플로우(콘/케이크/컵, 녹아 소실, 결과, 다음 날) 실행 오류 없음 확인, 소프트웨어 렌더로 프레임 캡처해 시각 점검 → 직원 가려짐·스푼 위치·컵 손·상자 대비 등 수정 완료

② 남은 것

마지막 두 수정(직원 위치 STAFF\_Y=126, 스탠드 스쿱 크기, 케이크 베어먹은 자국, 상자 뚜껑 색)은 코드 반영·구문/로직 테스트는 통과했지만 프레임 시각 재확인은 못 했어요

세부 튠업: 스쿱 쌓기 팔 길이가 트리플일 때 다소 길어 보임, 카운터 씬 클릭으로 애니 가속(현재 비활성) 등
