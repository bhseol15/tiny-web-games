## 4. 손님 모드 흐름 (v4)

```
재료 담기 → (사이드/맵기/국물/토핑 선택) → 💳 주문하고 결제하기
→ 결제 모달: 👛 지갑에서 카드 1장 터치해 꺼냄 → 카드를 리더기로 드래그(150px 이상) 또는 ⌨ 키보드 결제
→ 결제 성공 시 잔액 1회 차감 → 1.2초 조리 → 먹기 화면
→ 재료/토핑/사이드 클릭 · 숟가락 클릭(국물 3모금) → 전부 0이 되면 완식 모달
```

### 지갑 (v4 신규)
- 카드 4장: `MARA PASS`(마라탕 전용) · `SOPUNG CHECK`(체크) · `HOT POINT`(포인트) · `DRAGON BLACK`(프리미엄)
- 카드를 꺼내면 지갑 자리는 빈칸(반투명) 처리, "↩ 지갑에 다시 넣기"로 교체 가능
- 카드를 꺼내지 않으면 드래그·키보드 결제 모두 차단
- 결제 취소 시 주문 수정 가능, 잔액 부족 시 모달이 열리지 않고 안내

### 그릇 (v4)
- 300×300 정원(`aspect-ratio:1/1`), 재료·토핑은 국물 안쪽 원 영역(`overflow:hidden`)에만 배치
- 재료+토핑 수에 따라 4단계 자동 축소: 기본(≤6) → `.many`(7~9) → `.packed`(10~12) → `.jammed`(13+)
- 토핑은 그릇 **맨 윗줄**(노란 테두리 + 점선 구분선)에 표시
- 숟가락·젓가락 기본 위치를 그릇 가장자리로 이동해 재료 라벨을 가리지 않음
- 실측: 최대 구성(재료 9 + 토핑 4)까지 국물 원 밖으로 나가는 타일 0개

### 국물 색
| 맵기 | 색 |
|---|---|
| 순한맛 | 옅은 주홍 (#e58b4a) |
| 보통맛 | 붉은 주황 (#d2552b) |
| 얼얼맛 | 진홍 (#a8241a) |
| 마라폭풍 | 검붉음 (#6f0f12) + 안쪽 붉은 테두리 |
| 토마토 육수 | 맵기와 무관하게 토마토색 (#e0432c) — 맵기 색을 덮어씀 |
맵기 버튼 앞에 같은 색 점(●) 표시. 선택 즉시 0.5초 페이드로 전환.

### 먹기 규칙
- 재료·토핑·사이드 각 3입, 국물 3모금
- 남은 양 = 재료×3 + 토핑×3 + 사이드×3 + 국물3(재료가 있을 때만)
- **어떤 것을 먹어도 다른 항목이 리필되지 않음** (v2-1에서 수정, v4 재검증)
- 재료를 전부 먹으면 그릇에 "재료는 다 먹었어요! 국물·사이드를 마저 드세요" 표시
- 얼굴 표정: 기대 → 입 벌림(eating) → 행복(happy) → 복귀. 토핑/사이드/국물도 동일 애니메이션

| 메뉴 | 안내된 가격 |
|---|---:|
| 꿔바로 | 12,000원 |
| 크림새우 | 15,000원 |
| 복숭아 주스 | 3,000원 |
| 단무지 | 1,000원 |

- 주문 단계에서 사이드를 따로 선택·해제합니다.
- 주문서와 먹기 화면에서 마라탕과 구분하여 표시합니다.
- 주문한 사이드만 그릇 옆에 놓습니다.
- 꿔바로·크림새우·단무지는 접시, 복숭아 주스는 컵으로 표현합니다.
- 클릭하거나 터치하면 먹을 수 있고, 남은 양과 완료 상태를 표시하도록 수정 안내가 있었습니다.

### 5. 예산과 가격
- 최초 주문 가능 금액을 50,000원으로 설정했습니다.
- 사이드까지 포함하여 50,000원 이내로 주문하도록 요청했습니다.
- 이후 모드 전환 기능에서 시작 잔액을 50,000원으로 두고, 결제 시 차감·알바 성공 시 적립하는 구조로 확장했습니다.
- 잔액은 같은 브라우저에서 다시 열 때 불러오도록 저장하는 것으로 안내됐습니다.
- 알바로 잔액이 50,000원을 넘는 경우에도 1회 주문 상한이 별도로 유지되는지는 소스 및 플레이 확인이 필요합니다.

| 재료 종류 | 안내된 가격 범위 |
|---|---:|
| 채소 | 700~1,100원 |
| 면·떡 | 1,300~1,800원 |
| 어묵·햄·두부류 | 1,400~1,900원 |
| 해산물 | 2,200~2,600원 |
| 고기 | 3,800~4,200원 |

개별 재료별 최종 가격표는 대화에 제시되지 않았으므로 소스 확인이 필요합니다.

### 6. 손님 모드의 주문·결제
#### 요청한 흐름
재료와 사이드 선택 → 주문하고 결제하기 → 카드 가져오기 → 리더기에 카드 긁기 → 가상 결제 완료 → 먹기 화면.

#### 안내된 기능
- 마우스 또는 손가락으로 카드를 끌어 리더기에 긁습니다.
- 결제 취소 후 주문을 수정할 수 있습니다.
- 결제가 완료됐을 때만 주문 금액을 잔액에서 차감합니다.
- 잔액이 부족하면 안내를 표시합니다.

#### 반복된 결제 오류와 수정 안내
사용자가 여러 차례 손님 모드의 주문·결제 버튼이 동작하지 않는다고 보고했습니다.

1. 알바에서 손님 모드로 돌아올 때 잔액과 결제 버튼 상태 갱신.
2. 잔액 부족 안내 추가.
3. 결제 후 잔액 저장 및 카드 터치 중단 복구 처리 보완.
4. 재료 그림 준비 이전에 화면을 그리면서 이벤트 연결이 중단될 수 있다는 원인 설명 및 실행 순서 수정.

**주의:** 위 내용은 이전 답변의 수정 안내입니다. 실제 원인과 해결 여부를 이번 문서 작성에서 독립적으로 확인하지 않았으며, 마지막 수정 후 사용자의 정상 작동 확인도 없습니다. 결제 기능은 최우선 재검증 대상입니다.

### 7. 먹기 화면과 조작
- 먹을 때 얼굴이 기대하는 표정 → 입 벌리기 → 행복한 표정으로 변하도록 요청했습니다.
- 숟가락이 그릇에서 입으로 움직였다가 돌아오는 애니메이션을 추가하도록 요청했습니다.
- 별도의 ‘국물 한 모금 마시기’ 버튼은 삭제했습니다.
- 숟가락 자체를 누르면 국물을 한 모금 마시는 방식으로 변경했습니다.
- 젓가락이 마우스를 따라 움직이고, 그릇 속 재료를 누르면 해당 재료를 먹도록 요청했습니다.
- 휴대폰에서는 재료를 터치하여 먹는 방식으로 안내됐습니다.
- 숟가락과 젓가락의 네모 배경·테두리를 제거하도록 수정했습니다.
- 젓가락이 겹쳐도 숟가락 클릭을 막지 않도록 클릭 처리를 보완했다는 안내가 있었습니다.

### 8. 음식 이미지 변경 과정과 최종 방향
#### 변경 과정
1. 재료 형태·색·윤기와 붉은 국물·기름방울 등 사실적인 표현 요청.
2. 재료 선택 화면, 그릇 속 재료, 사이드에 음식 사진 적용 안내.
3. 사용자 확인에서 엉뚱한 사진 발견:
   - 소고기: 얇은 마라탕용 고기가 아닌 조리된 폭립 같은 사진.
   - 단무지: 김치 사진.
   - 크림새우: 식당 사진.
4. 외부 사진을 제거하고 재료 특징을 보여주는 간단한 일러스트로 변경.

#### 최종 표현 원칙
- 사진보다 재료를 정확히 알아볼 수 있는 간단한 일러스트를 사용합니다.
- 소고기는 흰 마블링이 있는 얇은 샤브샤브용 소고기로 표현합니다.
- 단무지는 노란 반달 모양으로 표현합니다.
- 크림새우는 흰 크림소스가 묻은 꼬리 있는 새우로 표현합니다.
- 일러스트와 재료 이름을 함께 표시합니다.
- 외부 사진 연결 없이 이미지를 표시하는 방향입니다.
- 알바 주문표에도 같은 재료 일러스트를 사용합니다.

### 9. 손님·아르바이트 모드와 돈의 순환
#### 손님 모드
- 시작 잔액: 50,000원.
- 가상 카드 결제 완료 시 주문 금액 차감.

#### 아르바이트 모드
- 손님 주문에 맞춰 재료와 맵기를 선택합니다.
- 정확하게 조리·제공하면 주문당 10,000원을 받는 것으로 안내됐습니다.
- 틀리거나 시간이 끝나도 돈이 차감되지 않는 것으로 안내됐습니다.
- 번 돈으로 손님 모드에 돌아가 다시 주문할 수 있습니다.

#### 모드 이동
손님 모드에서 소비 → 알바 모드에서 수입 획득 → 손님 모드로 돌아가 소비.

### 10. 알바 화면 구성
#### 손님 주문표
- 재료 일러스트, 이름, 필요한 수량 표시.
- 주문 맵기 확인.

#### 종류별 재료 선택창
다음과 같이 종류별로 묶어 배치하도록 수정했습니다.
- 채소
- 버섯
- 면·떡
- 두부·가공품
- 고기·해산물

#### 조리를 위해 선택한 재료 전용 창
- 선택한 재료와 수량을 별도로 표시합니다.
- 잘못 선택한 재료를 제거할 수 있도록 요청했습니다.
- 마지막 요청에서는 같은 재료를 한 번 누르면 선택, 다시 누르면 취소하는 토글 방식으로 변경했습니다.
- 선택·취소 결과를 별도 선택창에도 즉시 반영하도록 안내됐습니다.

**설계 확인 필요:** 주문표에 같은 재료를 2개 이상 요구하는 주문이 있다면 단순 선택·취소 토글과 충돌할 수 있습니다. 주문 생성 수량과 선택 방식의 일관성을 확인해야 합니다.

### 11. 60초 연속 주문 타임어택
#### 최종 요청 흐름
시작 → 재료 선택 → 조리하기·제공 → 새로운 주문 → 즉시 재료 선택 → 조리하기·제공 → 반복 → 시간 종료.

#### 핵심 조건
- ‘시작하기’는 한 세션의 맨 처음에 한 번만 누릅니다.
- 주문 하나를 완성하면 다음 주문을 자동으로 표시합니다.
- 다음 주문에서도 재료를 즉시 선택할 수 있어야 합니다.
- 매 주문마다 시작 버튼이나 ‘한 번 더 일하기’를 누르지 않습니다.
- 타이머는 60초이며 주문이 바뀌어도 초기화하지 않습니다.
- 성공한 주문마다 10,000원을 적립합니다.
- 완료 주문 수와 이번 세션 수입을 누적 표시합니다.
- 시간이 끝나면 결과를 보여주고 재도전 또는 손님 모드 복귀를 선택합니다.

#### 반복 수정 배경
자동으로 다음 주문을 보여주는 것만으로는 충분하지 않았습니다. 사용자는 다음 주문이 나온 뒤에도 시작하기를 다시 눌러야 하는 문제를 지적하며, 재료 선택이 곧바로 가능한 연속 진행을 재차 요청했습니다.

- [ ] 모바일에서 화면 겹침 없이 선택·결제·먹기가 가능하다.

### 14. 다음 작업자에게 전달할 핵심 요약
기존 HTML 게임의 재료·사이드·일러스트·카드 결제·먹기 기능을 유지하면서, 손님 모드의 결제 무반응을 실제 브라우저에서 재현하고 해결하는 것이 최우선입니다. 알바는 60초 동안 시작 버튼 한 번으로 주문을 연속 처리해야 하며, 재료 버튼은 재클릭 시 취소돼야 합니다. 게임 돈은 결제 시 차감되고 성공한 알바 주문마다 10,000원이 적립되어 두 모드 사이에서 공유되어야 합니다. 다음 수정본은 코드 검사뿐 아니라 실제 결제와 최소 3건의 연속 주문을 검증한 뒤 전달하는 것이 좋습니다.
