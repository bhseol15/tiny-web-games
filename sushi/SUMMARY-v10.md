# 🍣 냠냠 스시 — 작업 요약 (v10 기준)

> 단일 HTML 파일(바닐라 JS + Canvas + Web Audio)로 만든 귀여운 카와이 2D 회전초밥 웹 게임.
> 최신 파일: **`sushi-v10.html`** (이전 작업본: `sushi-game-v2 ~ v10.html`, 이후 버전은 `sushi-v{n}.html`)

---

## 1. 기획 인터뷰 결과

| 항목 | 결정 |
|---|---|
| 장르 | 손님이 되어 먹기 / 사장이 되어 만들기 (2가지 모드) |
| 플랫폼 | PC(마우스·키보드) + 모바일(터치), 반응형 단일 레이아웃 |
| 그래픽 | 귀여운 카와이 2D, 이미지 파일 없이 Canvas 직접 드로잉 |
| 기술 | 단일 HTML 파일, 바닐라 JS + Canvas, 외부 의존성 없음 |
| 진행 | 무한 모드 + 콤보 배율, 최고 점수 `localStorage` 저장 |
| 부가 | 캐릭터 표정/리액션, Web Audio로 코드 생성한 효과음 |

---

## 2. 공통 시스템

- **캐릭터 엔진**: 머리/머리카락/옷/모자 조합, 표정 7종 (idle·happy·yum·shock·angry·sad·full·sleepy), 눈 깜빡임, 뽈 터치, 둥실거림
- **효과음 (Web Audio)**: 먹기·실패·동전·팝·서빙 팡파르·화남·게임오버·녹차·콤보·클릭 (오실레이터 합성, 외부 파일 없음)
- **콤보 배율**: 5콤보 ×1.5 / 10콤보 ×2 / 20콤보 ×3
- **연출**: 점수 팝업 텍스트, 파티클 스파크, 화면 흔들림, 떠다니는 배경 도트
- **입력**: `pointerdown`(터치·마우스 통합) + 키보드 단축키, 첫 입력 시 AudioContext 활성화
- **반응형 스케일**: `U = clamp(min(W,H)/560, 0.6, 1.3)` 기준으로 모든 크기 계산, DPR 대응
- **타이틀 화면**: 떠다니는 메뉴 장식, 모드별 최고 기록 표시, 두 캐릭터

## 3. 🍴 손님 모드 (현재 사양)

### 흐름
1. 벨트(오른쪽→왼쪽)에 초밥·사이드·디저트·**와사비(함정)** 가 흐름
2. **벨트 접시 탭** → 접시가 포물선을 그리며 캐릭터 앞 **테이블(3자리)** 로 이동, 🧾 계산서에 가격 누적
3. **테이블 접시 탭 / 숫자키 1·2·3** → 젓가락이 손에서 접시로 뻗어 초밥을 집어 입까지 가져가는 애니메이션 → 냠냠 표정 + 점수
4. 먹은 접시는 테이블 오른쪽에 색깔별로 쌓임
5. **🧾 다 먹음** 버튼(Enter) → 계산서 화면 → **💳 카드(점수 +5%) / 💵 현금(3% 할인 + 거스름돈)** → "잘 먹었습니다! 🙏" → 결과 화면

### 자원 관리
- 💰 지갑 30,000원 시작, 지갑 − 계산서 < 접시 가격이면 못 가져옴
- 배부름 게이지: 먹으면 상승, 시간당 서서히 감소. **100% → 배 터져서 게임오버**
- 지갑이 바닥나면 자동으로 계산서 화면
- 5콤보마다 서비스 현금 +2,500원
- 와사비 접시: 가져오면 자리를 차지하고, 먹으면 매워서 배부름 +16·콤보 끊김·화면 흔들림

### 상 위 반찬 (고정 아이템, 쿨다운)
| 반찬 | 키 | 효과 | 쿨다운 |
|---|---|---|---|
| 🍲 장국 | 4 | 배부름 -15 | 15초 |
| 🟢 와사비 | 5 | 다음 초밥 점수 ×2 (배부름 +2) | 8초 |
| 🧄 마늘장아찌 | 6 | 콤보 타이머 4.5초로 연장, 배부름 -5 | 10초 |

### 📋 주문판 + 사장님 직접 전달
- 벨트 뒤 우상단에 요리사 모자 쓴 사장님 상주
- 📋 주문판 버튼 → 14개 메뉴 그리드 (7/5/2열 반응형, 돈 부족 메뉴는 흐림, Esc/닫기)
- 주문 → "네~ ○○ 하나요!" → 테이블 자리 "주문중…" 예약 → 약 2.2초 **도마 앞 칼질·통통 조리 애니메이션 + 진행 바** → "여기요~ 🍣" 팔 뻗기 → 접시가 큰 포물선으로 날아와 테이블 착지
- 한 번에 하나만 주문, 테이블 꽉 참/돈 부족 시 불가

### 디저트 보너스
- 배부름 50% 이상에서 디저트를 먹으면 **"디저트 배는 따로! 🍮 +10"**

## 4. 👨‍🍳 사장 모드 (현재 사양)

### 흐름
1. 손님 4명(모바일 3명) 자리에 손님이 앉아 말풍선으로 주문 (벨트 메뉴 10종)
2. 하단 메뉴 버튼(키 **1~9, 0**)으로 초밥을 만들어 벨트(왼쪽→오른쪽)에 올림
3. 벨트가 손님 앞을 지날 때 주문과 맞는 접시면 자동 서빙 → 가격 + 빠를수록 보너스 (×콤보)
4. 손님 인내심이 다하면 화내며 퇴장 → ❤️ -1 (3개 다 잃으면 게임오버)
5. 벨트를 2바퀴 돌도록 안 팔린 접시는 폐기 -100원

### 하루 단위 진행
- **하루 = 2분**, HUD에 `DAY N + ⏰ 남은 시간` (마지막 10초 빨간 깜빡임)
- 2분 종료 → 🌙 **영업 종료 정산**: 오늘 매출 / 서빙 손님 / 화낸 손님 / 폐기 접시 / 누적 매출
- "☀️ DAY N+1 영업 시작"(Enter) → 벨트·손님 초기화, ❤️ 3개 회복, 누적 매출 유지, 난이도 상승 지속

### 인내심 비표시
- 손님 말풍선에 **시간제한(인내심) 바 없음** — 손님 표정(평온 → 시무룩 → 화남 💢)만 보고 판단

### 버튼 레이아웃
- 화면 폭에 따라 10열 1줄 / 5열 2줄, 좁으면 아이콘 위·이름 아래 컴팩트 버튼으로 자동 전환

## 8. 검증 방법

- 공유 URL은 CSP(`sandbox`)로 인라인 스크립트가 막혀 브라우저 스크린샷 검증이 불가 → **Node `vm` + Canvas/DOM 스텁 헤드리스 시뮬레이션**으로 각 버전마다 다음을 확인
  - 두 모드 시작 → 플레이 → 게임오버/정산 → 재시작/메뉴 복귀
  - PC(1024×640)·모바일(390×800)·작은 창(700×500) 레이아웃 겹침 여부
  - 신규 기능 단위 동작 (젓가락, 반찬 쿨다운, 결제 카드/현금, 주문 전달, 메뉴 14종 주문·서빙 등)
