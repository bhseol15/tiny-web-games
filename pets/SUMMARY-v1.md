## 3. 유지해야 할 핵심 사양

### 3.1 피그미다람쥐
- 배색: 라이트 베이지(머리·등·꼬리) + 크림·아이보리 화이트(볼·가슴·배)
- 초기 오레오 배색(검정·차콜)은 폐기
- 몸통은 날씬하고 약간 길게, 둥근 얼굴, 작은 귀·코, 반짝이는 눈
- **수염 없음**
- 급식 시 **작은 종지 그릇을 다람쥐 바로 앞 바닥에 자동 배치**

### 3.2 게코도마뱀
- **릴리 화이트 모프 외형**: 머리·몸·꼬리·발은 베이지·연갈색, 등·옆구리는 넓은 크림·아이보리 무늬
- **초록색이 어디에도 남지 않아야 함** (사용자가 직접 보고한 문제)
- 상태·표정이 바뀌어도 배색 유지
- **간식 메뉴 없음, 산책 없음**, 간식·산책 요청 말풍선도 없어야 함

### 3.3 마리모
- 이름 붙이기, 수조 꾸미기, 광합성, 물갈이·수조 청소
- 빛·수질 상태에 맞는 표정·요청 말풍선
- 동물용 사료·급식 박스 대상에서 제외

### 3.4 공통 표정·말풍선

| 상황 | 방향 |
|---|---|
| 배고픔 | 배고픈 표정, "배가 고파요. 밥을 주세요!" |
| 집이 더러움 | 불편한 표정, "집을 깨끗하게 해 주세요!" |
| 상태 좋음 | 행복한 표정, "오늘은 편안하고 행복해요." |
| 돌봄 직후 | 짧은 감사·행동 반응 |
| 마리모 | 빛·수질에 맞는 요청 |

## 4. 급식 기능의 최종 사용자 흐름

### 4.1 준비 영역
1. 밥 주기 메뉴 → **팝업 없이** 상태창 아래 **먹이 준비 박스** 표시
2. 사료 선택 버튼은 **글씨 없이 그림(이모지) 중심**
3. 사료를 **클릭·터치**하면 종지에 담김
4. 사료 그림을 종지로 **드래그**해서 담는 방식도 유지
5. 종지 안 사료는 버튼과 **같은 모양**

### 4.2 배식
1. 준비 영역의 **'밥 주기'** 버튼
2. **동물 바로 앞 바닥에 종지가 자동 배치** (드래그 불필요)
3. 그릇은 넓은 접시가 아닌 **작은 종지** 형태

### 4.3 식사와 종료
- 사료가 **한 개씩 순차적으로** 사라지며 상태 수치 상승
- 빈 종지가 잠시 남은 뒤 정리
- 식사 후 **반드시 다시 밥을 줄 수 있어야 함**
- 취소·모드 전환·초기화 시 급식 상태와 타이머 완전 정리

## 5. 오늘 A단계: 16번 파일 정적 분석 상세

브라우저 실행이 불가능해 16번 HTML 소스(약 34KB)를 직접 읽어 분석했습니다. CSS 추출은 출력 길이 제한으로 다람쥐 '눈' 규칙 근처에서 끊겨, 그 뒤의 덮어쓰기 규칙(베이지, 릴리 화이트, `.moving-bowl` 위치, 미디어쿼리)은 확인하지 못했습니다.

판정 기준: **PASS(코드)** = 코드상 충족 / **FAIL(코드)** = 코드상 명백한 결함 / **미확인** = 코드만으로 판단 불가

### 5.1 외형
| 항목 | 판정 | 근거 |
|---|---|---|
| 다람쥐 베이지·크림 배색 | 미확인 | CSS 앞부분에 오레오 시절 검정·차콜 규칙(`#252525`, `#303030`, `#050505` 등)이 그대로 잔존. 뒤쪽 덮어쓰기 유무 확인 못 함 |
| 다람쥐 수염 없음 | 미확인 | 확인 범위의 `.snout:before/:after`는 크림색 타원(볼 덧칠)으로 수염 아님 |
| 게코 초록 잔존 | **미확인(위험)** | `.gecko .body{#93b67c}`, `.head{#a8c890}`, `.tail{#7f9e6d}`, `.snout{#d2e2a5}` 등 **초록 기본 규칙이 파일에 존재**. 09번 덮어쓰기 규칙의 우선순위에 의존하는 구조 |
| 상태 변화 시 게코 배색 유지 | PASS(코드) | `expression()`은 mood 클래스만 토글 |
| 마리모 | PASS(코드) | 몸통만 초록 방사형 그라데이션, 나머지 부위 숨김 |

### 5.2 메뉴·말풍선
| 항목 | 판정 | 근거 |
|---|---|---|
| 다람쥐 메뉴 8종 | PASS(코드) | 밥·간식·청소·똥·핸들링·산책 + 이름 + 집 꾸미기 |
| 게코 간식·산책 없음 | PASS(코드) | `gecko.acts` 4개(밥·청소·똥·핸들링) |
| 마리모 광합성·물갈이만 | PASS(코드) | `foods.marimo` 없음 → 급식 박스 미표시 |
| 게코 간식·산책 요청 대사 없음 | PASS(코드) | `need()` 문구에 해당 단어 없음 |
| 게코 '행복' 요청 대사 | **설계 공백** | 행복 <42면 "기분을 북돋아 주세요!"를 요청하지만 **게코에는 행복을 올리는 행동이 없음**(밥만 +6) |
| 말풍선 문구 | PASS(코드) | 사양 문구 확인 |

### 5.3 급식 흐름(다람쥐)
| 항목 | 판정 | 근거 |
|---|---|---|
| 팝업 없이 상태창 아래 박스 | PASS(코드) | `#feedInline` 섹션에 렌더링 |
| 사료 버튼 글씨 없음 | PASS(코드) | 이모지만 표시, 이름은 `aria-label`/`title`에만 |
| 클릭으로 종지에 담기 | PASS(코드) | `onclick` 토글 |
| **클릭마다 "접시 안에 놓아 주세요." 오류 토스트** | **FAIL(코드)** | `onpointerdown`에서 즉시 드래그 시작 → `onpointerup`이 이동량 검사 없이 드롭 실패 처리 → 평범한 클릭도 오류 토스트 발생, 말풍선 1.8초 덮어씀. 담기 자체는 `onclick`으로 동작 |
| 담기 규칙 | 참고 | 종류별 1개 토글, 최대 3조각 |
| 드래그 담기(마우스) | PASS(코드) | pointer 이벤트 + `setPointerCapture` |
| 드래그 담기(터치) | 미확인 | `.food-card`에 `touch-action:none` 유무 확인 못 함 |
| 종지 안 사료 = 버튼 모양 | PASS(코드) | 동일 이모지 참조 |
| '밥 주기' → 자동 배치 | PASS(코드)/위치 미확인 | `#movingBowl` 삽입 후 `beginEating` |

- **Node·브라우저 실행 검증은 하지 못했습니다.** Playwright 도구에 파일을 전달했으나 샌드박스에 도착하지 않는 문제가 3회 반복되어, 이 환경에서는 자동 브라우저 검증이 불가능한 것으로 판단됩니다.
- 이전 버전과의 **저장 데이터 호환은 보장하지 않습니다**(구조가 새로 작성됨).

### 6.2 사용자 직접 확인 우선순위
1. 게코 탭 → 초록색이 전혀 없는지
2. 다람쥐 → 밥 주기 → 사료 클릭 → 밥 주기 → 다 먹은 뒤 **다시 밥 주기가 되는지**
3. 먹는 도중 탭을 바꿔도 멈추지 않는지
4. 휴대폰에서 사료를 종지로 끌어다 놓기가 되는지

이상이 있으면 **어느 단계에서 어떤 현상**인지(가능하면 콘솔 오류 문구) 기록해 다음 수정에 전달합니다.

## 9. 알려진 문제 및 검증 상태

### 사용자가 직접 보고한 문제
1. **게코 색상이 바뀌지 않음** — 16번까지는 초록 기본 규칙 위에 덮어쓰는 구조였음. **v17은 초록 규칙을 아예 제거**했으므로 재발 가능성은 낮으나 실측 필요.
2. **밥을 한 번 주면 멈춤** — v17은 타이머·상태 리셋 로직을 새로 작성. 실측 필요.

### A단계에서 발견된 문제 (v17에서 대응)
3. 사료 클릭마다 "접시 안에 놓아 주세요." 오류 토스트 → v17: 8px 이동 임계값으로 클릭/드래그 구분

### 한계
- 모든 버전에서 **실제 브라우저 검증을 완료하지 못했습니다.** 문법 검사 통과 ≠ 정상 동작.
- 이 환경의 자동 브라우저 테스트 도구는 파일 전달 실패가 반복되어 사용 불가로 판단됩니다.

## 12. 후속 작업용 요약

> **v17(전면 재작성)** 을 기준으로 작업합니다. 이전 16번 이하 파일은 참고용이며 더 이상 수정하지 않습니다. 피그미다람쥐는 베이지·크림 화이트, 날씬하고 귀엽게, 수염 없이. 게코는 베이지·연갈색 바탕의 릴리 화이트 무늬, 초록 규칙 없음, 간식·산책 메뉴·대사 없음, 핸들링으로 행복 회복. 급식은 팝업 없이 상태창 아래 박스, 이모지 버튼, 클릭(담기)/8px 드래그 구분, 종지 최대 4개, '밥 주기' 시 동물 앞 자동 배치, 0.85초 간격 소모, 1.2초 후 빈 종지 정리, 재급식 가능. 마리모는 광합성·물갈이. **브라우저 실측은 아직 0회**이므로 다음 작업은 사용자 실측 결과(게코 색상, 반복 급식, 탭 전환, 모바일 드래그, 콘솔 오류)를 받아 수정하는 것부터 시작합니다.
